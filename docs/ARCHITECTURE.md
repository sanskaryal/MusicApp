# Architecture

Vite builds React into apps/music-web/dist. A threaded Python HTTP server serves that build, JSON API routes, and byte-range MP3 playback on port 8765. During development Vite proxies /api to the same backend. SQLite uses WAL and per-operation connections, with foreign keys enabled. All persistent files live under data/ (override with MUSIC_DATA_DIR).

The library contains validated 11-character YouTube IDs. Search calls yt-dlp flat playlist JSON with a bounded timeout, a short cache, and limited concurrency. Playback requests upsert metadata and schedule a download in a two-worker executor. Downloads have a bounded pending count, timeout, size/duration limits, disabled user configs/plugins, and fixed output filenames. SQLite records queued/downloading/ready/error states; startup recovers interrupted jobs as retryable errors. A ready file is reused. Downloads never block HTTP requests. Polling updates the client while work is pending.

Queue entries have separate IDs so repeat tracks are supported. Queue ordering updates are transactional and require the exact current ID set. Playlists use a join table with unique track membership. Likes are stored on tracks. The client keeps the selected track and volume in localStorage, while library collections remain on the backend. Audio uses one persistent HTML audio element, independent of navigation. Selecting a new track clears the previous source while its download is pending. A request sequence prevents slow earlier clicks from taking over newer playback.

Security boundary: trusted personal use. Default bind is 127.0.0.1; MUSIC_HOST=0.0.0.0 enables private LAN access, without authentication. Reject cross-origin mutations, non-JSON bodies, oversized payloads, malformed IDs and traversal. Do not expose this server directly to the public internet. Downloader subprocesses use fixed argument arrays and no shell. MP3 streaming handles HEAD and single byte ranges, including suffix ranges. No service worker caches API responses or audio.
